# Harvest Valley (repo: Harvestworks)

A cozy isometric production-chain farming game that runs in the browser.
Live at: https://zcgrimshaw.github.io/harvestwork/
Also linked from: https://zerocrunch.ca/harvest-valley

Saves live in each player's own browser. Nothing is sent to a server.

## Layout

- `src/` — the actual source. Edit here, never in the built root files.
  - `index.html` — page structure and UI
  - `data.js` — items, recipes, stations, discoveries, contracts
  - `art.js` — placeholder pixel art
  - `game.js` — gameplay logic, rendering, saving
- `build.sh` — builds the playable files into the repo root from `src/`, and stamps a build id
- root `index.html`, `*.js`, `version.json` — the built game GitHub Pages serves. **Don't hand-edit these** — they're regenerated by `build.sh`.
- `CHANGELOG.md` — what changed in each tagged release
- `ROADMAP.md` — ideas not built yet, picked up later

## Workflow for a change

1. Edit the relevant file(s) in `src/` only.
2. Run `./build.sh` to regenerate the root build.
3. Add a line to `CHANGELOG.md` under a new version heading.
4. Commit, tag the release (`git tag vX.Y`), and push with tags.

## Design vocabulary (so edits stay consistent)

- **Discovery tokens (DT)** are the currency that unlocks Discoveries. They are separate from score points — everything the player does should earn score, regardless of DT.
- Game arc: early game = a steady stream of discoveries (learning), mid game = planning and unlocking, late game = layered automation toward factories.

## Scope discipline

- Keep changes scoped to the files a request actually touches — `data.js` for new items/recipes/discoveries, `game.js` for logic/rendering/saving, `art.js` for visuals, `index.html` for UI/layout.
- Don't re-explore the whole codebase for small, well-specified changes (e.g. "add a Silo building to data.js, cost 80, +200 storage").
- Prefer Sonnet for routine edits (new content, balancing tweaks, UI fixes). Reserve Opus for real architectural decisions (e.g. reworking the save format, restructuring the discovery tree).
